# PMO 生命周期验收清单

## 工作流与统筹视图

- [ ] 工作台按未立项、项目库、已完成、已废弃自动汇总，且不提供直接改类操作。
- [ ] 申报中覆盖草稿与学院内审核，首次提交 PMO 后才离开该阶段。
- [ ] 登记有效立项文件号后，项目自动进入项目库且默认为未实施。
- [ ] 只有完成 PMO 材料完备确认的项目才归属已完成。
- [ ] 任一非终态项目可申请废弃，缺少原因、操作人或审批人时拒绝流转。

## 评审与配置

- [ ] PMO 可维护版本化的主阶段、细进度模板、角色和流转规则。
- [ ] 评审步骤可新增、停用、删除和排序，且每一步能独立开启评审批次。
- [ ] PMO 可从待评审项目池选取部分项目进入已开启批次；未选项目保持在项目池。
- [ ] 通过、退回和意见均保留到项目历史；退回项目重新提交 PMO 后才能再次入池。
- [ ] 细进度可记录负责人、计划/完成日期和说明，且不会自动阻断合法主阶段流转。

## 留痕与回归

- [ ] 所有状态流转保留来源状态、目标状态、操作人、审批人、原因、交付物/文件号和时间。
- [ ] 新工作流版本不改写存量项目的版本；迁移操作可追溯。
- [ ] 覆盖项目创建、立项文件登记、评审批次选入/通过/退回、材料完备确认、废弃等后端测试。
- [ ] 前端验证四大视图筛选、项目详情历史、评审批次选择和配置管理入口。

## Phase 1 React 工作台

- [ ] 右侧可见“批量操作”及纳入推进、调整 Stage、添加事项、应用工作包和禁用的加入批次入口；旧“批量流转”结构不再出现。
- [ ] 勾选多个项目后，可在右侧原地添加多个事项、保存常用事项或将组合保存为工作包；下发成功后列表立即显示进展摘要。
- [ ] 项目详情可从常用事项选择或新增单项目临时事项，并可更新、完成和重开事项。
- [ ] 总览和阶段跟踪视图可切换；推荐列不创建事项，缺失事项显示“—”，个人列配置保存在浏览器本地。
- [ ] 1366×768 下无需横向滚动即可看到项目、当前进展、下一关键节点和右侧批量操作；操作切换不影响左侧列表位置、排序、勾选或滚动。
- [ ] 完成前在浏览器中验证“选项目→添加事项/纳入推进/应用工作包→列表回显→详情办理”路径，不能仅以 API 或构建结果验收。

## 工作台信息层级与事项过程记录

- [ ] 右侧操作台随视口剩余高度延展；页面下方仍有空间时，操作台不应先出现内部滚动条，预检结果归入操作台底部。
- [ ] 中窄屏统计区和五张 Stage 卡保持紧凑或横向滚动，不退化成占满整屏的单列巨卡。
- [ ] Stage 下不显示旧 current_status；列表 Stage 单元只显示固定治理 Stage。
- [ ] 当前进展仅显示两项，严格按逾期、等待外部、进行中、未开始，以及重点关注、计划日期、优先级排序；暂停、不适用和已完成仅在展开中显示。
- [ ] 打开添加事项时可搜索常用事项并加入清单；保存常用事项后下一次立即可搜索复用。新建临时事项首屏仅见名称、内容、状态。
- [ ] 事项可记录多条 Progress Log；默认不投影到项目时间线，勾选同步后才显示。项目时间线不得展示负责人、日期、备注、优先级等细碎编辑；完整 AuditEvent 通过折叠入口查询。
- [ ] 中窄屏操作台折叠而不挤压项目表，数据导入位于工作台主体之后；更新时间仅显示日期。
- [ ] 主流程排序仅依赖 flow_group 与 sequence_rank；暂停阻塞、取消/不适用/跳过退出下一关键节点计算。
- [ ] 新项目没有学院内部流程默认事项；应用未立项 PMO 工作包后，下一关键节点从项目自身 PMO 审核事项开始。
- [ ] 项目可软删除、查看已移除列表并带理由恢复，删除与恢复均保留审计。
- [ ] 纳入、暂缓和跨年重新纳入生成独立推进周期；未立项项目可登记提前准备，特批推进仍归未立项卡片且可单独筛选。
- [ ] 项目类型字典与部门顺序可维护；`project_type` 是唯一项目分类，排序遵循 project_type → department → 项目回退顺序；历史 `category` 不参与新功能。
- [ ] 专业教学软件、实践教学场所及其历史别名均能按同一 `project_type` 分类筛选；PMO 新增分类不需要理解或填写内部代码。
- [ ] 完成、里程碑、进展和外部约束结论日期默认当天且可修改，计划完成日期保持空白。
- [ ] 所有治理写操作均验证持久化、API 投影、局部 UI 回显与刷新后存在；失败不显示乐观成功态，业务页面无原生 alert/confirm/prompt。
# External Constraint 验收补充

- [ ] 当前适用阻断性约束集合为空的项目显示为外部条件已具备；PMO 显式建立但尚未确认范围的阻断约束作为待处理例外。
- [ ] 只有未解除的阻断性约束影响 `external_constraints_cleared`；非阻断约束不影响结果。
- [ ] 当前有效预算及其来源在列表、详情与导出中可解释，且不由 Dashboard 重复计算。
- [ ] 约束结论失效会回到未解除并保留原结论；约束不再适用会标记为不适用，而不是重新阻断项目。
- [ ] 工作台可通过行空白区选择项目，同时按钮、链接、输入控件不会误触发行选择；快速办理返回后保留批量模式与勾选。
- [ ] 常用事项、工作包和外部约束模板可归档/恢复，归档模板不再出现在默认选择器且不影响历史实例；Progress Log 删除需软删除理由。
- [ ] PMO 可从工作台手动新增项目；项目移除要求操作人和原因，刷新后项目不在日常列表或导出中，但审计和数据库记录保留。
- [ ] 批量新增临时外部约束可显式保存为常用模板；点击“外部条件待处理”仅筛选仍有未解除阻断约束的项目。
- [ ] 顶部四项主统计与“外部条件待处理”次级筛选分层展示；项目类别可筛选，且停用类别不会出现在默认选择器。
- [ ] 工作台“推进中”卡是管理视图：正常推进与特批未立项项目同时计入，特批项目仍显示在未立项卡；两类项目均可单独或混合暂缓。
- [ ] 总览表以“推进情况”合并展示下一关键节点、另一项重点事项和准确的 `+N`；底层下一关键节点规则不变。
- [ ] 软件项目以“项目分类 · 采购属性”展示，场所项目以“项目分类 · 地点”展示；结构化属性缺失时显示“未设置”，不增加独立表格列。
- [ ] 快速办理的完成表单在宽窄视口均显示结果、日期、说明、里程碑和同行操作按钮，不出现逐字换行、竖排或裁切。
- [ ] 批量操作区实时显示当前已选数量和有效预算合计；可展开名单并取消单个项目，筛选后仍保留已选对象。
- [ ] 项目名称最多两行并可悬停查看全文；推进情况首项不重复“下一”标签，第二事项按进行中、等待外部、重点关注排序。
- [ ] 快速办理清晰分为本次进展与事项设置；详情页按项目概况、当前办理、关键治理信息和历史记录呈现。
- [ ] 项目基本信息保存对成功和失败均有明确反馈；名称与采购属性修改后，当前投影、审计和刷新后的数据一致。
- [ ] 详情页依次呈现项目概况、外部约束、当前办理、关键里程碑和历史记录；无外部约束时该区保持紧凑。
- [ ] 快速完成表单按完成信息、里程碑、操作区分组；勾选里程碑不造成按钮错位或内容出框。
- [ ] 在 1440×900、1366×768、1100×768、900×768、768×1024、600×900 下，工作台无页面级横向溢出，项目表不被操作台压缩为窄条，超宽内容仅在自身容器滚动。
- [ ] `1100–1439px` 展开批量或快速办理时，操作台保持至少 320px 宽并覆盖部分项目表；存在明显收起入口，遮罩和 Esc 均可关闭。
- [ ] `≤1099px` 页面顺序为 Stage 带、项目列表、操作台、导入区；导入区始终位于最下方。
- [ ] 项目详情编辑时，名称和修改理由均有必填标识；缺少任一字段后点击保存会显示字段错误并聚焦首个错误，服务端失败保留原填写内容。
