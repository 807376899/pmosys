# 2026-08-21：External Constraint 作为轻量治理对象

- 决定：引入 External Constraint，而不把预算审核、备案和准入重新做成固定项目状态。
- 原因：外部治理条件可跨 Stage 存在，且与具体办理 Work Item 并不一一对应；使用三态解除投影可让统计口径可解释。
- 边界：推荐 Stage 不做强绑定；Phase 1 每项约束至多关联一个主 Work Item；BusinessRecord 选择器和多对多关联留待后续。
| 2026-08-22 | 外部条件已具备以“无未解除阻断约束”为准 | 零个适用阻断约束的项目也可直接具备外部条件；该口径不代表内部材料齐备 |
| 2026-08-22 | 模板采用归档而非默认物理删除 | 已经下发的事项、工作包和外部约束快照必须永久保留；进展记录软删除且必须说明原因 |
| 2026-08-22 | 外部约束写操作必须形成可见闭环 | 批量/单项目创建、范围确认和结论登记均以数据库持久化、API 投影、局部回显和刷新后仍存在为验收；批量临时约束可显式沉淀为常用模板 |
| 2026-08-22 | 顶部统计分主盘与次级提示 | 项目库总量/预算和外部条件已具备数量/预算为主指标；办理中项目及涉及预算仅作为可点击的次级筛选提示 |
